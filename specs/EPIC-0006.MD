# Epic 5: Future Recommendation Intelligence

## Objective

Evolve the recommendation system beyond profile-independent personalization.

This epic should only start after the MVP is live, feedback is being collected reliably, and baseline metrics are available.

---

# SPEC-021: Trending Recommendations

## Owner

Node/NestJS

## Goal

Use aggregate user behavior to identify restaurants that are currently popular.

## Signals

- Likes
- Positive ratings
- Repeat recommendations
- Low dislike ratio
- High acceptance rate

## Output

```text
Trending Nearby
```

## Acceptance Criteria

- Trending score is computed per restaurant.
- Trending can be filtered by location.
- Trending does not replace personalization; it complements it.

---

# SPEC-022: Collaborative Filtering

## Owner

Python for modeling
Node/NestJS for serving/integration

## Goal

Recommend restaurants based on behavior from similar users.

## Requirement

Only start once there is enough first-party interaction data.

## Acceptance Criteria

- User similarity is computed from interaction history.
- Restaurants liked by similar users can influence ranking.
- Cold-start fallback remains available.

---

# SPEC-023: Context-Aware Recommendations

## Owner

Node/NestJS first
Python later if used in ML models

## Goal

Make recommendations sensitive to the user’s current situation.

## Context Examples

- Time of day
- Day of week
- Meal type
- Weather
- Occasion
- Distance tolerance

## Acceptance Criteria

- Context is stored in recommendation sessions.
- Context can affect scoring.
- Context is available for future ML training.

---

# SPEC-024: Exploration Engine

## Owner

Node/NestJS first

## Goal

Avoid overfitting to known preferences by occasionally showing new but reasonable options.

## Strategy

```text
80% strong match
20% exploration
```

## Acceptance Criteria

- Exploration rate is configurable.
- Explored recommendations are tracked.
- Exploration does not significantly hurt recommendation quality.

---

# SPEC-025: Recommendation Explanations

## Owner

Node/NestJS

## Goal

Give users confidence in the recommendation.

## Example

```text
Recommended because it matches your budget and you usually like Japanese restaurants.
```

## Acceptance Criteria

- Explanation is generated from score breakdown/features.
- Explanation is short and user-friendly.
- No internal ML details are exposed.

---

# SPEC-026: A/B Testing Framework

## Owner

Node/NestJS

## Goal

Compare recommendation strategies safely.

## Examples

- RuleBasedV1 vs RuleBasedV2
- Personalized vs Popular Nearby
- Different scoring weights
- Different list sizes

## Acceptance Criteria

- Users can be assigned to strategy variants.
- Recommendation sessions store variant info.
- Metrics can be compared across variants.

---

# SPEC-027: LLM Re-Ranking

## Owner

Python or separate AI service
Node/NestJS for orchestration

## Goal

Use an LLM as an optional final ranking layer over already selected candidates.

## Important Constraint

LLM should not replace candidate generation or deterministic scoring.

## Acceptance Criteria

- LLM only receives a small candidate set.
- LLM output is validated.
- Fallback exists.
- Cost and latency are monitored.

---

# Epic 5 Completion Criteria

Epic 5 is complete when at least one advanced intelligence capability is productionized and measurable without compromising the reliability of the MVP recommendation flow.
