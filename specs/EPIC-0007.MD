# Epic 6: Product Experience & Experimentation

## Objective

Optimize the recommendation experience to help users make decisions faster and increase recommendation acceptance.

This epic focuses on:

- Recommendation presentation
- User decision flow
- Feedback collection UX
- Experimentation
- Conversion measurement

The recommendation model is not the primary concern here.

---

# SPEC-028: Recommendation Experience

## Owner

Frontend + Node/NestJS

## Goal

Define how recommendations are presented to users.

## Initial Recommendation Layout

```text
Today's Pick ⭐

Restaurant A

────────────────────

Other Great Options

Restaurant B
Restaurant C
Restaurant D
Restaurant E
```

## Acceptance Criteria

- Hero recommendation is visually emphasized.
- Secondary recommendations are clearly separated.
- User is not overwhelmed with options.
- Recommendation session is linked to UI state.

---

# SPEC-029: Recommendation Refresh Flow

## Owner

Frontend + Node/NestJS

## Goal

Allow users to request a new recommendation batch.

## Flow

```text
Current Session

↓

User doesn't like options

↓

Refresh Recommendations

↓

New Session
```

## Rules

- Previously shown restaurants should be suppressed.
- Refresh count should be tracked.
- Refreshes should generate new recommendation sessions.

## Acceptance Criteria

- User can request a new batch.
- Refresh creates a new session.
- Recommendation diversity increases.

---

# SPEC-030: Recommendation Conversion Tracking

## Owner

Node/NestJS

## Goal

Measure whether recommendations lead to meaningful actions.

## Events

### Recommendation Viewed

```text
Recommendation displayed
```

### Recommendation Opened

```text
User opens details
```

### Recommendation Accepted

```text
User indicates interest
```

### Recommendation Rejected

```text
User dislikes recommendation
```

### Recommendation Converted

Future:

```text
Navigation started
Reservation made
Restaurant visited
```

## Acceptance Criteria

- Funnel metrics exist.
- Conversion rates can be measured.
- Events link to recommendation sessions.

---

# SPEC-031: Recommendation Fatigue Prevention

## Owner

Node/NestJS

## Goal

Avoid repeatedly showing the same restaurants.

## Rules

Track:

- Recently shown
- Recently rejected
- Frequently recommended

Apply suppression windows.

## Acceptance Criteria

- Repetition decreases.
- User experience remains fresh.
- Suppression rules are configurable.

---

# SPEC-032: User Preference Refinement

## Owner

Frontend + Node/NestJS

## Goal

Improve recommendation quality by gradually learning more preferences.

Instead of asking many onboarding questions upfront:

```text
Do you like outdoor seating?

Do you prefer quick meals?

Do you enjoy fine dining?
```

Ask occasionally after recommendations.

## Acceptance Criteria

- Preference collection is incremental.
- Friction remains low.
- Additional preference signals are captured.

---

# SPEC-033: Recommendation Quality Dashboard

## Owner

Node/NestJS

## Goal

Provide business visibility into recommendation performance.

## Metrics

- Acceptance Rate
- Like Rate
- Dislike Rate
- Refresh Rate
- Session Completion Rate
- Restaurant Rating Average
- Recommendation Conversion Rate

## Acceptance Criteria

- Metrics are available for review.
- Recommendation quality trends are visible.
- Product decisions can be data-driven.

---

# Epic 6 Completion Criteria

Epic 6 is complete when:

- Recommendation UX is standardized.
- Refresh behavior is implemented.
- User decision funnels are measurable.
- Recommendation fatigue is controlled.
- Product teams can evaluate recommendation quality.
